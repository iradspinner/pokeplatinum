# Phase 3: what the base ROM changed from vanilla

Written 2026-09-15 by diffing `Platinum Unlocked - Challenge - Adjusted v1.1.nds` against the byte-exact Rev 1 ROM built from pokeplatinum. Every number below comes from that comparison. The raw diff data is kept in `notes\diff\` (`file_diffs.json`, `member_diffs.json`, `synth_overlay_9.bin`).

Ian's guidance: keep overworld events, trainer edits, and Pokemon stat and move edits where possible; flag anything else. The "keep" set turns out to be larger than "about 80 fights", and there is also code in the base that Ian may or may not remember adding. Questions for Ian are marked **Q**.

> **Corrections since this was written.** Read these before trusting the sections they name; the original text is kept below as the record of what the diff looked like on the day.
> - **Section 1, Trainers row, and section 2B:** there is **no expanded trainer format**. The party data is vanilla layout; the only non-vanilla piece is the high byte of `ivScale` (ability slot and gender nibbles). Determined 2026-09-15 from the ROM, detail in `phase3-answers-and-trainer-format.md` section 2.
> - **Section 2A:** `HandleInput_SelectMove+0x8E` is not a viewer hook; it makes HMs forgettable from the summary screen. Ported with the constant edits (2026-09-19).
> - **Section 2D:** answered 2026-09-20. The scripts call exactly one custom command, `Dummy088`, three times in `scripts_common`, as part of a "use another Repel?" prompt. Only that command is ported; the rest of the region is dropped. See `phase3-scripts-and-events-plan.md`.
> - **Section 2E:** `TeachMove+0x5B` is reusable TMs (it skips `Bag_TryRemoveItem`), not HM-forgetting. Ported 2026-09-20.
> - **Section 1, "tool side effects":** `mmodel.narc`'s six changed members are not building models. They are overworld sprites Ian placed into the dummy slots (members 55, 56, 59, 64, 65, 73; 1,640-byte placeholders in vanilla, real sprites in the base ROM) and 43 object events on 35 maps use them. Found in play 2026-09-20; carried over 2026-09-26.
> - **All five Qs** are answered in `phase3-answers-and-trainer-format.md`. Items marked as tool side effects (sprite re-saves, heights, the vitamin records) were judged DSPRE noise by a session, not by Ian, and not carried over. **That judgement was wrong for everything but the vitamins** (next entry).
> - **Section 1, the rest of "tool side effects", re-examined 2026-09-26** against the base ROM of 2026-08-31 with `tools/oxide/editcheck.py`, which compares content after undoing everything a DSPRE re-save changes (file version, file and block sizes, palette bit 15, sprite encryption, LZ compression). Nearly every changed member is a real edit, and together they are a visual overhaul, none of it in Oxide yet: **a new Pokemon sprite set** (Black and White style) with custom shiny palettes, in `pl_pokegra` (1,713 edited members across 486 species: 418 back sprites, 465 front, 417 shiny palettes, 348 normal palettes; the other 1,075 changed members are re-saves), with its companions `height.narc` (298 entries, 201 species) and `pl_poke_data` (Moltres and Dragonite), and 26 form palettes in `pl_otherpoke`; **new battle scenery**, in `pl_batt_bg` (73 of 78 members: 18 backgrounds, one screen, 54 palettes) and `pl_batt_obj` (every terrain's two platforms and the HP box palette); **the superbosses' battle sprites** in `trfgra` (the four player classes Red, Gold, May and Steven fight as); **a title screen** (`titledemo` 11 and 12); **four box wallpapers** (`box` 64 to 74); **UI palettes** (`pl_plist_gra` 4, 13, 16, `pl_b_plist_gra` 23, `batt_obj` 71); **the Pocket PC's icon** (`item_icon` 441, the Vs. Seeker's tiles); and one byte, 0x77 to 0, in `waza_particle` 484, purpose unknown. The vitamin records stay judged as damage: the base ROM lost each vitamin's EV gain (HP Up's 10 became 0) while raising the vitamin EV cap, so vanilla's records are kept.
> - **The visual overhaul comes over whole** (Ian, 2026-09-27), in this order, each archive registered with `verify_narcs.py`: carried over so far, the superbosses' battle sprites (`trfgra`, the base ROM's own eight files, byte for byte), and the battle scenery (`pl_batt_bg`, the base ROM's own archive; `pl_batt_obj`'s 45 platforms, one misc sprite and the HP box palette as PNGs, compared by content), and the title screen and UI palettes (the title logo's tiles and palette as the base ROM's own files; `box`, `pl_b_plist_gra` and `batt_obj`, the base ROM's own archives; `pl_plist_gra`'s three palettes by entry), and the one unexplained byte in `waza_particle` 484 (Shadow Force's particles); and the Pokemon sprite set (`pl_pokegra`, 948 sprites with their keys and 765 palettes rewritten in their changed entries; `pl_otherpoke`'s 26 form shiny palettes; 134 sprite heights, now imported by `import_base_rom.py`; and Moltres's and Dragonite's shadow records in `pl_poke_data`). The whole overhaul is now in; each archive is in `verify_narcs.py`'s default list.
> - **The last three items, identified 2026-09-27, with Ian's rulings the same day.** **Section 2E's two bytes at arm9 `0x0EC478`** are the Lass entry of `sTrainerEncounterBGMs` (`src/field_bgm.c`): the class number 3 was overwritten with 0x0456, the entry's own music id (`SEQ_EYE_GIRL`), so no class matches it and every Lass falls back to the default, `SEQ_EYE_KID`. A slip; **not carried over**. **Section 2C's palette patch** is a hue shift, not a shiny patch: a routine written over the Battle Arcade code (arm9 `0x20500BC`, with a 64-entry cosine and sine table at `0x205003C`) rotates a 16-colour palette's 15 visible colours with the standard hue-rotation matrix, by one of 32 steps up to about 20 degrees (personality bits 16 to 20) in either direction (bit 21). The personality is the last one `Pokemon_GetValue` or `BoxPokemon_GetValue` read, or in battle each battler's; `Pokedex_GetDisplayForm` clears it, so the Pokedex shows standard colours, and no hook reaches the shared menu-icon palettes. It is 19 hook sites, not six: eight in arm9, three in battle animations, five in the battle overlay, one each in the Hall of Fame, its PC viewer and egg hatching. **Being ported** on `carry-over-hue` with the personality passed to the sprite code directly. **The encounter `unown_table` and `rate_form` changes** are closed: 98 `unown_table` changes are 0 to 1, which the game reads the same; the 17 real ones set every Solaceon Ruins room to 8 (only ! and ?), and Oxide's tables hold no Unown at all, so vanilla stays. `rate_form` is a switch (0 West Sea, else East); only Route 212 north and south really change, to the pink West Sea Gastrodon, which Ian wants: the encounter track sets those two fields.

## 2. Code edits (these do NOT carry over automatically; each becomes a C change or is dropped)

The base's `arm9` differs from vanilla at 38 places and eleven overlays differ. Mapped to the decomp's function names:

**A. A synthetic overlay and its loader.** `data/weather_sys.narc` member 9 is a 90 KB block that vanilla does not have; only 578 bytes of it are used. `NitroMain+0x2D` is patched to load it at boot (DSPRE's "ARM9 expansion" patch; loader code sits over unused assertion strings at arm9 `0x0F93D0`, `0x100E20`, `0x101574`). The block contains four labelled routines: `EV+IV_Viewer`, `no_items` (no items in trainer battles), `frame_unlock_settings` (frame-rate unlock), `chain_candy` (Rare Candy chaining). Hooks that jump into it: `HandleInput_Main+0x34` and `SetMonDataFromMon+0x1B2` (summary screen, for the viewer: the first makes R cycle a mode byte, the second swaps the seven stat reads for IV or EV reads), `PartyMenuCB_LevelUp+0x276` (candy), four hooks in ov16 (battle: `+0x42`, `+0x154`, `+0x26E8`, `+0x2E6E`, `+0xDEC8`, `+0xEDE0`), one each in ov12, ov13, ov84, ov86, ov87, ov119, and two in ov5.
**Correction (2026-09-19):** this entry originally listed `HandleInput_SelectMove+0x8E` as a viewer hook. It is not one, and it does not branch into the synthetic overlay at all: it replaces the call to `Item_IsHMMove` with `nop; movs r0, #0`, so HMs can be forgotten from the summary screen's move-select. Put it with the `TeachMove+0x5B` HM-forget edit in section 2E.

**Q:** These look like the ds-pokemon-hacking "code injection" patches applied through DSPRE. Which of the four do you want in the port? Under approach C each is a small C edit (hg-engine has all four as config toggles too, so the design is known). The synthetic-overlay mechanism itself is dropped; the decomp has no need for it.

**B. Expanded trainer party format. (Superseded, see the corrections at the top: the format is vanilla.)** `TrainerData_BuildParty` (1,026 bytes) is fully rewritten and `Trainer_Encounter+0x6E` is edited. This is the community "expanded trainer data" patch that lets trainer Pokemon carry custom IVs, EVs, natures, abilities and so on; it is why `trpoke.narc` entries are 16/32/48/108 bytes. **Q:** Confirm which patch this is (the DSPRE option name or the guide you followed), so the same fields can be read back correctly. Under C, pokeplatinum's trainer format is the vanilla one; the port will need the decomp's trainer struct extended to hold those fields (hg-engine's `trainer_data.h` is the model), and the 561 party records converted. This is a real chunk of Phase 3.

**C. Palette-loading hooks.** `PaletteData_LoadBufferFromFile+0x48`, `LoadPaletteWithSrcOffset+0x1E`, `BufferPokemonSpritePlttData+0x50`, `SpriteSystem_LoadPlttResObj+0x3C`, `CharacterSprite_LoadPalette+0x30`, `Pokedex_GetDisplayForm+0x2`, `Pokemon_GetValue+0x2`, `BoxPokemon_GetValue+0x2` all branch into the expansion. Together with `Pokemon_IsPersonalityShiny+0x18` changing `8` to `0xFF`, this reads as a shiny-related patch (raised shiny odds plus custom shiny palettes or per-form palettes). **Q:** What is it?

**D. Script commands over Battle Arcade code.** arm9 `0x05003C` to `0x0505BC` (~1.4 KB), which in vanilla is `ScrCmd_CallBattleArcadeLobbyFunction`, `SelectBattleArcadeChallengers` and neighbours, is overwritten with new code and a table, and `ScrCmd_Dummy088` is replaced with a 60-byte routine. Something added custom script commands by sacrificing Battle Arcade functions. **Q:** Do you know what this is? If any of the 91 edited scripts use these custom commands, the port has to reimplement them; if not, it can be dropped. (Battle Arcade would be broken in the base ROM as a result; "Unlocked" may have been intended to bypass it.)

**E. Small constant edits, all understood:**
- `Pokemon_CheckItemEffects+0x298` and `CalculateEVUpdate+0x38`: vitamin EV cap 100 to 252 (hg-engine's `UPDATE_VITAMIN_EV_CAPS`).
- `Options_Init+0x12/+0x24`: default options changed (text speed / battle style).
- `ApplyButtonModeToInput`: 2-byte change (button mode default).
- `TeachMove+0x5B`: a conditional branch made unconditional (probably "HMs can be forgotten").
- `UseVsSeekerFromMenu+0xC` (two places): a constant changed.
- ov73, ov9: one small edit each. ov14 (trainer AI): ten single-byte edits, consistent with the AI bug fixes in the ds-pokemon-hacking battle_edits guide (items 35 to 43). ov16 `+0x1309C..+0x130BE`: a 4-entry table (10, 30, 50, 70) set to 255, and `+0xEA3C`, `+0x10D58`, `+0x2D046` small edits.
**Resolved 2026-09-20.** All four unexplained ov16 edits are identified: `+0x1309C..+0x130BE` is `BattleControllerPlayer_CheckObedience`, its badge-scaled disobedience thresholds set to 255 so traded Pokemon always obey; `+0xEA3C` is a literal, `MAX_EVS_ALL_STATS` changed from 510 to 0, which makes the EV routine early-out every time so battling grants no EVs; `+0x2D046` is `UpdateGauge`, doubling the HP bar drain; and `+0x10D58` is the no-items-in-trainer-battles change. Only the HP bar is ported so far.

**Q:** For the ov14 AI fixes, which ones did you apply? Under C they are one-line C fixes in `src/battle/trainer_ai/`, and the ones you did not apply can be applied too.
