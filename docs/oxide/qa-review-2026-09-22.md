## Findings

Seven in all: one that changes what the pin actually achieves, two normal
defects in the new tools, four nits. Each was confirmed by reading the cited
lines in this checkout; the first was also confirmed against the generated
`build/build.ninja`.

### 1. The pin does not reach the build's 227 Python invocations

**Severity:** the reviewer called it pre-existing, since the exposure predates
the pin. It matters most here because the pin was the fix for that exposure
and the Makefile comment says it succeeded.

**Where:** `Makefile` lines 30 to 40. The comment says meson "bakes whichever
interpreter runs it into build.ninja, which is what makes one variable here
cover all 227 invocations." `PYTHON` and `MESON` then pin only the interpreter
that runs `meson setup`.

**What actually happens:** every generator script is registered with
`find_program('xxx.py', native: true)` (for example `tools/jsoncnv/meson.build`
lines 5 to 14, and the same in `tools/scripts`, `tools/ordergen`,
`tools/debug`, `tools/postconf`). Meson records the script's path as the
command, not an interpreter plus the script. A rule from this checkout's
`build/build.ninja`:

```
COMMAND = env PYTHONPATH=/home/ian/pokeplatinum/build /home/ian/pokeplatinum/tools/jsoncnv/event.py ../res/field/events/events_empty.json res/field/events/zone_event.narc.p/events_empty
```

The kernel resolves the script's own `#!/usr/bin/env python3` against PATH at
ninja's run time. On this box that is `/usr/bin/python3`, which is 3.14.4, the
interpreter the pin exists to avoid. `build/build.ninja` contains no reference
to `oxide-python` at all.

**Consequence:** `make rom` still generates event data, map matrices and the
encounter archives on the flaky interpreter. The tracker's claim that the build
was "diagnosed and pinned away on 2026-09-22", and the CLAUDE.md line that the
Makefile "goes through" the wrapper, are both wrong for the build step. The
one check in the URGENT block that would have caught this, "wipe `build/`,
rebuild, and the ROM should come out byte-identical", passes either way
because the flake is intermittent.

**Fix options, for the Overseer to choose:**

- Put the pinned interpreter's directory first on PATH for the ninja step in
  the Makefile, so the shebang's `env python3` resolves to it. Smallest change.
- Or pass each generator to meson as `[python, script]` so the interpreter is
  baked into the rule. Touches every `find_program` in five meson files and
  drifts from upstream pret.
- Either way, the proof is `grep oxide-python build/build.ninja` or a rule that
  names the venv's python, plus a `python_flake_repro.py` style check run from
  inside a generator.

### 2. `--show` output is contaminated by the summary line

**Severity:** normal. **Where:** `tools/oxide/convert_battle_scripts.py`
lines 230 to 244.

`main()` prints the rename-map summary ("rename map: N entries, derived
from...") to stdout unconditionally, and a further "AMBIGUOUS" block whenever
`conflicts` is non-empty, before `--show N` writes the converted script to
that same stdout. The intended use, redirecting `--show N` into
`res/battle/scripts/effects/effect_script_NNNN.s`, puts one or more lines of
English at the top of an assembly file. The fix is to send the summary and the
warning to stderr, or to suppress them under `--show`.

### 3. The wrapper's middle tier gives a bare interpreter and says nothing

**Severity:** normal. **Where:** `tools/oxide/oxide-python` lines 39 to 47,
with `tools/oxide/pinned_python.py` lines 44 to 63.

The wrapper resolves in tiers: `OXIDE_PYTHON`, then `~/.venvs/oxide`, then
whatever `uv python find 3.13` returns, then `python3` with a warning. The
third tier is a uv-managed 3.13 with no ndspy, Pillow or openpyxl installed,
and it prints no warning. On any machine where uv is present but the venv was
never built, the new `pinned_python.ensure()` call in eight tools re-execs a
tool that was working onto that bare interpreter, and tools that import ndspy
at module scope (`import_base_rom`, `verify_narcs`, `scriptdis`,
`donor_moves`) die with a missing-module error that nothing explains. On this
box the venv exists, so the tier is dormant, but the Overseer or a fresh
checkout would hit it. Fix: warn on that tier as the last one does, or only
prefer it over `sys.executable` when the venv is present.

### 4. Converted scripts lose the two blank lines after the include (nit)

`tools/oxide/convert_battle_scripts.py` line 54 defines `HEADER` as the
include plus two blank lines, matching Platinum's own effect scripts
(`effect_script_0006.s` has exactly that). Line 151 does
`HEADER.rstrip("\n")`, which strips every trailing newline, not one, so the
body starts on the line after the include. `--selftest` cannot see it because
its comparison drops blank lines.

### 5. The bootstrap block is pasted into eight tools (nit)

The same four lines (`import os as _os, sys as _sys`, the `sys.path.insert`,
`import pinned_python`, `pinned_python.ensure()`) sit in the `__main__` block
of `bulk_events.py`, `bulk_scripts.py`, `bulk_text.py`, `donor_moves.py`,
`import_base_rom.py`, `import_moves.py`, `scriptdis.py` and `verify_narcs.py`.
The `sys.path.insert` is redundant when the tool is run directly, since Python
already puts the script's own directory first. Not a defect; a change to how
the pin bootstraps has to be made eight times.

### 6. `import_moves.py` misreports where effect names came from (nit)

Lines 388 to 391 print "N named from hg-engine, M unnamed", but N counts
every name without `_UNUSED_`, which includes effects named by the older
move-name fallback when `battle-effect-names.json` had no entry. The counts
should be split so the sentence is true.

### 7. Duplicate filtering in the converter (nit)

`body_lines()` at line 68 and `body_lines_from_text()` at line 205 of
`convert_battle_scripts.py` contain the same comment-strip, blank-skip and
directive-skip logic. One should call the other.

## What the review did not find

Nothing against the guard's two invariants, the ones the URGENT block asked
for most: it found no path by which `ensure()` loops (the `GUARD` environment
variable is set before the exec and checked first), and no import-time
re-exec (every call is under `__main__`). It raised nothing against the
rename-map derivation in the converter or its 161-of-198 selftest claim.
Absence of a finding is not a pass; those still want the independent checks
the URGENT block lists.
